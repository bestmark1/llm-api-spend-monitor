# Общие правила Spender

Единственный источник общих проектных правил для всех клиентов. Дополняет
глобальные инструкции владельца. [AGENTS.md](AGENTS.md) служит входом;
текущее состояние хранится в [handoff](docs/handoff.md), задачи — в
[backlog](docs/backlog.md).

## Границы продукта

Spender — существующее local-first SwiftUI-приложение для строки меню macOS.
Оно получает метрики напрямую от провайдеров; секреты находятся в Keychain,
снимки и настройки — локально. Назначение и ограничения — в [README](README.md).

Стоимость, баланс и токены имеют независимые доступность и происхождение.
Отсутствующее значение не равно нулю; оценка не становится официальной
метрикой. Сбой usage не должен без основания уничтожать валидные costs.
Изменение этих контрактов требует явного согласования и регрессионных тестов.

Секреты и содержимое Keychain не выводятся в чат, логи или отчёты. Для
проверок используй обезличенные fixtures. Реальные обращения к аккаунтам,
новые сервисы, зависимости и платные вызовы отдельно согласуются.

## Режимы работы

Desktop и Herdr используются **по очереди**, с одним ответственным
координатором. Общие ограничения и принятые решения действуют в обоих режимах.
Активный режим записывается в handoff; одновременная работа двух сред не нужна.

### Desktop

В Desktop работают Codex и Claude: Codex может передать задачу Claude,
а Claude — Codex. Постоянной команды из пяти агентов в этом режиме нет.
Существующий порядок через приложения Codex/Claude и назначения моделей
из действующих глобальных инструкций соответствующего клиента сохраняются.
Таблица Herdr их не заменяет. Настройки основной сессии молча не меняются.

### Терминальный режим — Herdr

Архитектор/координатор совмещает архитектуру и координацию: читает состояние,
декомпозирует запрос, определяет приоритеты, выдаёт задачи, организует
независимую проверку, принимает результат относительно критериев и ведёт
handoff/backlog. Искусственное разделение этой роли не вводится.

Назначения владельца для Herdr; координатор и тестировщик обновлены
по явному запросу 15 сентября 2026. Назначения остальных ролей сохранены:

| Роль | Модель | Reasoning | Среда и ответственность |
|---|---|---|---|
| Архитектор / координатор | Codex GPT-5.6 Sol (`gpt-5.6-sol`) | high | Существующая панель Codex в Herdr; архитектура, приоритеты, декомпозиция, распределение, приёмка и состояние проекта |
| Senior-разработчик | Claude Opus 5 | high | Существующая панель Claude в Herdr; сложная реализация, отладка, техническое ревью чужих изменений |
| Frontend и тестирование | Codex GPT-5.6 Sol (`openai-codex/gpt-5.6-sol`) | high | Существующая панель через **pi** в Herdr; SwiftUI-интерфейс, тесты, независимая проверка пользовательского сценария |
| Middle-разработчик | Muse Spark 1.3 Contributor — Free | high | Существующая панель через **pi** в Herdr; ограниченные задачи по конкретной спецификации, механические изменения, небольшие исправления |
| DevOps | DeepSeek v4 Flash | high | Существующая панель через **pi** в Herdr; окружение, сборка, инфраструктура, подготовка распространения, выявление ненужных файлов и зависимостей |

Технические ID модели/провайдера и actual reasoning проверяй в текущей
конфигурации или состоянии сессии, а не угадывай по отображаемому названию.
Default клиента не доказывает настройки открытой панели. Расхождение сообщи
владельцу до выдачи задачи; самостоятельно модели и аккаунты не заменяй.
Способ работы через pi — часть назначения, не отдельная роль.

Используй существующие панели по необходимости. Для реализации назначай
исполнителя, для независимого ревью — другого агента; координатор принимает
по доказательствам, а не по сообщению автора «готово». Каждая выдача содержит
ID, ожидаемый результат, границы файлов, ограничения и критерий приёмки.
Исполнителю явно сообщается, что он не один в репозитории: чужие изменения
сохраняются. Пустая очередь и blocked-задачи не служат поводом будить агента.

Перед длительным заданием Senior и тестировщику проверь доступные сведения
о лимитах и последних ошибках. По сообщению владельца, координатор и
тестировщик используют общую подписку Codex; доступность одного не доказывает
доступность другого. После сообщения о восстановлении допустима одна короткая
проверка в его панели. Context usage и стоимость сессии не равны остатку квоты.
Непоказанные остаток и время сброса называются неизвестными. При quota error
сохрани результат и блокер; повторять запросы без новых сведений не нужно.

### Backlog и передача

Единая очередь — [docs/backlog.md](docs/backlog.md). Ответственный —
архитектор/координатор. Обновляй её при выдаче, блокере, передаче на review
и завершении. Обязательные поля: стабильный ID; задача и ожидаемый результат;
приоритет; статус `todo`, `in_progress`, `blocked`, `review` или `done`;
назначенная роль; зависимости/блокер; критерий приёмки; ссылка на решение,
спецификацию или проверку. `done` — только после предусмотренной приёмки.
Старые планы переносятся в очередь после проверки актуальности, а не целиком.

Handoff содержит текущий режим, завершённый этап, следующий шаг,
незакоммиченные изменения с назначением, выполненные проверки и непроверенное,
решения владельца. Он не копирует backlog. История дефектов и проверок
хранится в соответствующих отчётах; устойчивые правила — здесь.

При смене проекта сначала сохрани точку остановки старого. Для исполнителя
предпочтительна новая сессия в той же панели: она читает абсолютный путь
нового проекта, AGENTS.md, CLAUDE.md, handoff и назначенную задачу backlog.
Перед работой проверь рабочую папку, Git и применённые модель/reasoning.
Сброс контекста выполняется после согласования перехода и сохранения
результатов; закрывать панели и менять модели для него не требуется.

Смена режима или сессии не разрешает commit/push, публикацию, установку,
перезапуск приложения, изменение архитектуры или возобновление другого проекта.

## Проверки и внешние изменения

Перед изменением проверь Git и ближайший код/тесты; исправляй только согласованный
объём. Для бага сначала получи воспроизведение. Исполнитель сообщает команды,
реальные результаты и пропуски; независимый проверяющий проверяет критерии.

- Для документации: согласованность указателей, статусов и моделей, проверка
  ссылок и whitespace, включая новые неотслеживаемые файлы.
- Для кода: релевантные тесты, затем согласованный общий gate из
  [README — Tests](README.md#tests). Отдельно указывай skipped и ограничения
  подписи/Keychain/Accessibility. Зелёные unit-тесты не подтверждают live API.
- Для интерфейса: проверка нативного пользовательского сценария и визуальный
  осмотр; недоступное UI-окружение фиксируется как непроверенное.

`scripts/install-local.zsh` — не просто сборка: он заменяет установленное
приложение и запускает его. Установка, перезапуск, подпись с изменением
настроек аккаунта, deploy/publish/push, удаление данных, Keychain, кэша или
окружения требуют явного разрешения. Роль DevOps такого разрешения не даёт.
Commit — только по запросу владельца и только согласованных изменений;
push — по отдельному явному поручению. Рабочие изменения других сохраняются.
