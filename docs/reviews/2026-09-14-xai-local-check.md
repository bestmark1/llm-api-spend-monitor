# SPM-003 — локальная проверка установленного xAI

14 сентября 2026. Read-only диагностику выполнил Frontend/тестировщик в
существующей pi-панели `w2:p9`; координатор проверял доступ к UI отдельно.
Новой реализации и её приёмки в этом задании нет.

## Подтверждённое

- Запущена `/Applications/Spender.app`, PID на момент проверки `64321`.
- Версия `0.1.0`, build `2`, bundle ID `com.bestmark.LLMSpendMonitor`.
- По проверке тестировщика: подпись Apple Development, sandbox включён,
  `codesign --verify --strict` завершился с кодом 0.
- `nm` установленного бинарника показывает `XAIProvider.fetchTeamID`,
  `fetchBalance`, `fetchUsage`. Наличие клиента подтверждено; соответствие
  бинарника всему текущему HEAD этим не доказывается.
- В сохранённых preferences xAI известен и не входит в hidden: карточка
  включена. `isVisibleByDefault: false` в исходниках не описывает уже
  сохранённый пользовательский выбор.
- Снимок xAI в cache существует, `issue = authentication`.
- `fetchedAt = 2026-09-12T13:57:11Z`. Состояние прочитано
  `2026-09-14T06:34:32Z`; нового запроса к API не было.

## Интерпретация и непроверенное

В [RefreshCoordinator](../../LLMSpendMonitor/Services/RefreshCoordinator.swift)
`ProviderClientError.invalidCredential` отображается как `authentication`.
При последующей ошибке ранее сохранённые метрики и их `fetchedAt` могут
сохраняться: этот timestamp нельзя объявлять точным временем последнего отказа.

Скрытая в preferences карточка и отсутствие XAI-клиента исключены в пределах
проверенных файлов. Причина ошибки авторизации, наличие и валидность ключа
сейчас **не установлены**. Cache не доказывает текущее наличие credential.
Также не доказано, что неподходящий ключ — единственная возможная причина.

Координатор подтвердил процесс и версию отдельно. Computer Use не смог
получить состояние `/Applications/Spender.app`: два ответа
`timeoutReached (-10005)`. При этом чтение UI Finder работает.
Это блокер инструментального доступа к панели, не доказательство зависания
приложения или отказа billing API.

## Решение и следующий шаг

### Дополнение: скриншот владельца 14 сентября

Владелец предоставил скриншот открытого Spender. На нём видна раскрытая
карточка `xAI · Grok`, статус `Action needed` и текст:
«The saved credential was rejected. Replace it in Connections.»
Таким образом, ожидание подтверждения видимой карточки/текста статуса снято.
Сам скриншот и посторонние данные аккаунтов в репозиторий не переносились.

Это свидетельство отображаемой ошибки, а не нового API-запроса. Скриншот
не устанавливает HTTP-код, причину отказа, тип сохранённого ключа или
отсутствие поддержки xAI. По официальной
[инструкции xAI](https://docs.x.ai/developers/management-api-guide)
Management API использует отдельный Management key из Settings → Management
Keys, не обычный inference API key. Какой тип использовал владелец, неизвестно.

Локальная диагностическая часть принята координатором. Изначально SPM-003
был blocked до уточнения типа ключа и согласованной проверки подключения.
Затем владелец сообщил, что самостоятельно подставил Management key и расходы
теперь отображаются. Координатор закрыл диагностический этап: локальные факты
проверены, восстановление отображения — сообщение владельца, не независимая
live-проверка. Исходная причина отказа полностью не установлена; влияние
IP-ограничений экспериментально не проверялось. Секрет не передавался.
Следующий шаг — пользовательская подсказка SPM-005, а не новый запрос к аккаунту.
Отклонение одного credential не делает провайдера несовместимым.
Новый ключ при необходимости вводит сам владелец непосредственно в приложении,
не в чате; изменение подключения отдельно согласуется.

Keychain и auth-файлы не читались. Координатор и тестировщик не выполняли
live API, платные вызовы, изменение ключей/настроек, сборку, тесты,
переустановку, перезапуск, commit или push. Остаток квоты тестировщика
не показан; quota error в этой задаче не возникал. Модель и сессия сохранены.
